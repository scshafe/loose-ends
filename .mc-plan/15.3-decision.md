Phase 15.3 implemented task CRUD as a narrow core slice: title/body create and update, flat list/show/delete, and server-side UUID prefix resolution shared by HTTP and CLI. Parent moves, status transitions, tags, JSON output flags, and stdin body handling remain deferred to their later planned phases.

The HTTP API returns the spec error envelope, and CLI commands talk only to the configured service URL instead of opening Postgres directly. A second migration adds an `updated_at` trigger for the core tasks table so future update paths keep timestamps consistent.
